## The step to be careful about

The 8 Austin pages ship `index, follow` and **will shadow live React routes
that already rank.** That was a deliberate choice and the mechanism is verified,
but it changes the stakes: the DFW suite ships entirely `noindex`, so a fault
there is invisible until the flip. A fault on an Austin page lands immediately
on a URL already earning traffic.

Worth one deliberate pass over those 8 pages before the upload rather than
after — they are listed in the manifest, and `verify-routes.sh` covers each one
for content, questionnaire, tagging, phone number, description, schema and
indexing state.

## Resolved — the /home-loans/ duplication

The DFW copy of `/home-loans/` measured **82% identical** to the Austin page
it was cloned from (the other seven cross-market pairs sit at 30-39%, because
those DFW pages were written from a template with their own copy).

`home-loans` was added to `ALWAYS_NOINDEX` in `go-live/set-indexing.js` on
9 September 2026, so:

- `/home-loans/` (Austin) stays `index, follow` — the original keeps ranking
- `/texas/dallas-fort-worth/home-loans/` stays `noindex` in both modes
- it was removed from `sitemap.xml`, which otherwise would have asked a
  crawler to index a page telling it not to

The page still works and stays in the DFW nav; it just does not compete for
listings. Same treatment as about, privacy and terms.

**One detail worth knowing:** that list applies the full staging value,
`noindex, nofollow, noarchive, nosnippet`. On a page in the main nav the
`nofollow` means outbound links from it are not followed. Nothing is
orphaned — every DFW page is reachable from every other page's footer, and
the consolidated products that treat home-loans as their hub are .htaccess
301s rather than pages. If passing link equity from it matters, that one
page would need `noindex, follow` instead; say so and it is a small change.

## Already verified — do not redo this

So that review time goes on the open questions rather than the settled ones.

**Read from `landing-manifest.json` -> `build_gates`, which the pipeline writes
only on a run where every gate passed.** A failing build records nothing, so
this list cannot claim a check that did not happen.

**Blocking — these stop the build:**

- **`build-all.js invariants`** — each clone carries the Self-Employed dropdown; nothing links off the DFW suite; every live page exists; each Austin page has its questionnaire, meta description, JSON-LD, working mobile nav, no ratings in schema and is not noindex; the market home keeps its nav geometry.
- **`check-links.js`** — every internal href and in-page anchor on every built page resolves — to a page on disk, a live React route, or an .htaccess redirect. Assets must exist as files. *(1406 internal links, 55 in-page anchors, across 26 pages)*.
- **`per-builder gates`** — each builder asserts its own edits landed — a MISS is fatal, so a needle that stops matching stops the build rather than silently producing an unedited page.
- **`build-package.js`** — every referenced image is present in upload/; all pages are in the staging indexing state; the shell schema carries no aggregateRating and is still valid JSON.
- **`go-live/set-indexing.js`** — after flipping, re-reads every page and confirms its robots and googlebot meta match the mode and robots.txt *(manages 24 pages (16 DFW + 8 Austin))*.

**Reporting — these tell you, and are clean:**

- **`audit-integrity.js`** — duplicate ids, dangling ARIA references, label/for mismatches, analytics events that disagree with this manifest, CRM fields a form posts that this manifest does not declare, one manifest row per page with matching pageview events, sitemap entries that are permanently noindex, and the eyebrow contrast rule present and identical in both stylesheets.
- **`check-images.js`** — every referenced image exists, every hero class has a CSS rule, and no DFW photograph carries more than two pages.
- **`audit-lead-identifiers.js`** — every submitting page lands in exactly one CRM branch under the documented form_type conditions.
- **`verify-routes.sh`** — run against a live host: canonical URLs, URL variants collapsing, retired-route 301s, intermediate 404s, source docs not served, indexing state, the Austin static pages, and that every image a page references is actually served (including CSS backgrounds) *(sitemap carries 24 URLs)*.

**Exercised in a real browser, not just statically:**

- calculator arithmetic against an independent computation, including the zero-rate case and negative escrow inputs
- the nine-panel questionnaire: per-panel required-field validation, email format, the consent gate, and the spam honeypot
- the CRM payload as actually posted — no field is sent that this manifest does not declare, so nothing is silently dropped
- the mobile nav panel opening, closing and toggling aria-expanded

Every one of these has been made to fail on purpose at least once. A gate
nobody has watched fail is not known to work — two in this project were
reporting success while doing nothing.

## Rollback

Keep the pre-deploy copy of the web root. Nothing in this package touches the
React bundle or the database, so reverting is a file restore plus
`set-indexing.js staging` if the flip already ran.
