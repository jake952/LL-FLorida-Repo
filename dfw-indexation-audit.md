# DFW Indexation Audit

Answers the technical half of the 21 September 2026 handoff. Regenerated by `_build/build-dfw-indexation-audit.js` on every build — do not hand-edit.

## The finding, in one paragraph

Every one of the ten pages was serving `noindex, nofollow, noarchive, nosnippet`. Nothing else was wrong with them: all ten returned HTTP 200, none sent an `X-Robots-Tag` header, every canonical was self-referencing, `robots.txt` did not restrict anything, and Googlebot and Bingbot received byte-identical responses. The block was one meta tag, and it was there on purpose — it is the staging value this project has always applied. **The deployment step that replaces it was never run.** `go-live/set-indexing.js production` rewrites the meta on every page and installs the production `robots.txt`; the site was uploaded without it.

**The live `robots.txt` is neither of the two this project ships.** It is the host default — SiteGround serves this when no robots.txt has been uploaded, and none ever was. It restricts nothing, so it did not cause the block, but it carries no Sitemap: directive. So no sitemap has ever been advertised to a crawler that did not already know about it.

## Internal links

All 821 links counted here are ordinary `<a href>` anchors in served HTML. Nothing that requires JavaScript to appear is counted as a link.

Every one of the ten has 15 inbound source pages, and the cross-link matrix in the handoff's Step 6 is satisfied in full.

### The one weakness, and it is the important one

The route into the DFW cluster from the rest of the site is a single hop wide. 6 Austin program pages each carry one "Dallas–Fort Worth Options" anchor, and **all of them point at the market home**, not at any of the ten. The Austin React shell's link to DFW is injected at runtime by `landing-assets/spa-service-areas-link.js` and does not exist in the served HTML — the raw response for `leahylending.com/` contains 0 occurrences of `dallas-fort-worth`.

The market home is one of the six pages held back from the index. Under the old staging value it also said `nofollow`, so the production flip would have made the ten pages indexable while the only door into them told crawlers not to walk through it. That is fixed — see the remediation report — but the underlying shape is worth knowing: **the ten pages have deep internal linking among themselves and one shallow connection to the indexed site.**

## What this document does not say

- It does not say the pages are indexed. Nothing in a repository can. That is Google Search Console and Bing Webmaster Tools, after the corrected files are uploaded.
- It does not say the pages will rank, or that answer engines will cite them.
- It does not clear any content, claim or compliance question. The claims still awaiting an evidence record are listed in `LAUNCH-BLOCKERS.md`, and making a page indexable is exactly the event several of those entries were written to gate.
